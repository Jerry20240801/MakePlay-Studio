# 造玩工坊（Zaowan Workshop）

> 说一句话，做一个能玩、能改、能验证的小游戏。

造玩工坊是一个本地优先的小游戏创作工作台：AI 负责生成与修改，机器负责检查与真实试玩，你负责决定采纳哪个版本。正式支持解谜逃脱、回合潜行、知识闯关、卡牌对战、对话叙事五种小型游戏。

**当前状态（2026-11-15）**：五个模式包、创作工作台、自动体检（29 条规则 / 6 条一键修复）、三档审查（本地 / 云端 AI / 两者）、Issue 回归闭环、素材与导出均已实现；新增 **Tiled 地图导入**（外部工程 → 网格配方，见下文）与 **修复基准** `pnpm bench`（5 个缺陷夹具 × 算法 / 算法优先+AI / 纯 AI）。真实模型证据：首次生成、Issue 修复、盲修、插话、云端审查（均为 `Qwen/Qwen3.8-Flash-Next`，单模型小样本，不代表成功率）。实际结果与未验证项以 [实施状态](docs/implementation-status.md) 和本页“诚实边界”为准。

## 导入外部工程：Tiled 地图

首页“八个可以直接玩的模板”右侧有 **导入 Tiled 地图**，也可直接调用 `POST /api/import/tiled`（body：`{ map: <Tiled JSON>, name? }`）。

- 支持 Tiled 正交、有限尺寸 JSON 地图（`.tmj` / `.json`，CSV 或未压缩 Base64 图层），尺寸 ≤ 20×20。
- 墙：名为 `walls` / `collision` / `墙` 的图块层，或图块属性 `collides=true` / class 为 `wall`。
- 对象（按 class/type 或名称识别，中英文均可）：`player` 起点、`key/item`（属性 `itemType`、`count`）、`door`（`itemType`、`count`）、`exit`、`guard`（多边形/折线作为巡逻闭环，`facing`、`every`）、`switch`（`flag`、`mode`）、`gate`（`flag`）。有守卫时自动用潜行包。
- 四周没墙会自动加外墙；未识别对象、落在墙上的对象、不合法的巡逻路径都写进导入报告，**不静默丢弃**。
- 导入报告写入工程 `origin`，Agent 的 `inspect_project` 能读到；导入后立即跑本地体检。
- 示例：[docs/examples/tiled/vault-two-rooms.tmj](docs/examples/tiled/vault-two-rooms.tmj) 故意把钥匙放在门后并带一个无法识别的“火把”对象：导入 → 体检报 `grid/key-behind-door` → 一键修复或让 AI 修 → 同一检查回归通过（由 `tests/integration/import.test.ts` 自动验证）。

## 修复基准：算法能修多少、AI 补多少

`pnpm bench`（即 `node tools/bench-repair.mjs`）对 `tests/fixtures/bench/` 下 5 个缺陷关卡跑三种方式，结果写入 `docs/competition/evidence/bench-<日期>/`（`results.json`、`summary.md`、真实运行事件流 `runs/`）：

| 夹具 | 缺陷 | 纯算法（本机实测 ×3） |
|---|---|---|
| B1 | 钥匙在门后 | 3/3，0 次模型调用 |
| B2 | 门要的钥匙不存在 | 3/3，0 次模型调用 |
| B3 | 机关门没有开关（标记已声明，本地规则不报） | 0/3 → 需要 AI |
| B4 | 出口被墙封死（规则能报，无算法修复） | 0/3 → 需要 AI |
| B5 | 复合：钥匙在门后 + 钥匙数不够 + 出口被堵 | 0/3（算法修掉前两处，剩一处）→ 需要 AI 兜底 |

AI 与“算法优先 + AI 兜底”两臂需要模型：`BENCH_MODELS=模型A,模型B BENCH_API_KEY=... BENCH_REPEATS=3 pnpm bench`。未提供 Key 时 AI 臂记为 skipped，不写任何 AI 数字。

## 首屏：左侧工程，右侧开始创作

```text
┌ 工程 · 新建游戏 ┬ 把一句话，变成能玩的小游戏。            ┐
│ 我的工程        │ [ 我想做一个……                ] [开始创作] │
│ · 钥匙与出口    │ 类型：解谜 / 潜行 / 知识 / 卡牌 / 对话    │
│ · 熔炉决斗      │ 五个可以直接玩的模板                    │
└─────────────────┴──────────────────────────────────────────┘
```

1. **左侧工程栏**：列出已有工程；顶部“新建游戏”直接创建一个空白工程并进入工作台，不需要先配置。
2. **一句话输入 + 一个主按钮“开始创作”**：先选游戏类型（默认解谜），不要求用户先懂配方或工具。
3. **五个能直接玩的模板**：两次点击内进入工作台，游戏已经在中央可玩；模板创建后不会先弹一堆设置，也不自动跑 AI。
4. **一个 AI 状态入口**：已连接时显示模型名；未连接时明确说明“不会生成，只能先建骨架或手动编辑”。

首屏不出现 CDP、Recipe、ContractSet、buildId 等内部术语。需要解释时放进折叠的“为什么可信”，而不是放在第一屏。

## 两条开始方式

### 模板：先玩到，再改

`首页 → 使用模板 → 工作台 → 游戏已可玩`

- 创建后中央给三个新手动作：`试玩一下`、`让 AI 改一个地方`、`导出游戏`。
- 模板附带的创作底线用一句人话说明，例如“钥匙和门的规则不会被 AI 悄悄改掉”；详细面板默认折叠。
- 模板不自动触发 AI 任务；用户想改时再发起 `modify`。

### 想法：AI 真正生成第一版

`首页输入想法 → 确认类型 → 任务编译卡 → 开始生成 → 试玩 AI 候选 → 采纳或继续改`

- **模型已连接**：创建最小有效骨架后自动发起 `initial_generation` 任务。首次生成必须有非空配方 diff；只有 `inspect_project → prepare_review` 不算生成。
- **模型未连接**：明确显示“尚未生成你的游戏”，给三个出口：`去连接 AI`、`先手动编辑`、`改用可玩模板`；绝不把骨架说成 AI 成品。
- AI 候选默认不覆盖当前版本；在中央切换 `当前版本 / AI 候选`，确认后再采纳。

## 工作台：三栏，游戏优先

```text
┌ 工程 / 会话  ┬ 项目名  v3·可玩 / v4·AI候选待确认   试玩 | 编辑 | 导出 ┐
│ + 新建会话   │ 中央：真实游戏预览                │ 改动 / 验证 /   │
│              │ 当前版本切换、重新试玩             │ 底线 / 版本     │
│ 工程         │ 有问题时：问题条 + 三个动作        │ 素材（默认折叠）│
│ · 当前工程   ├──────────────────────────────────┤                 │
│ 会话         │ AI 对话与步骤卡 + 持续输入框        │                 │
└──────────────┴──────────────────────────────────┴─────────────────┘
```

- **左栏是工程，不是 `run-xxxx` 原始列表**：上面列出所有工程；当前工程下展开会话（状态、时间、AI 候选）。顶部按钮首页是“新建游戏”，项目页是“新建会话”。
- **“新建会话”只清空当前会话视图**，不会删除旧线程；发送第一条要求后才创建新的 `threadId`。
- **中央上方永远是游戏**（最小 360px 高），问题条紧贴游戏上方；下方是 AI 对话与步骤卡。任务结束后输入框变为“继续这个话题”，创建同 `threadId` 的新运行。
- **右栏**默认折叠，按 `改动 / 验证 / 底线 / 版本 / 素材` 分 tab；有问题或 concern 时自动打开对应项。
- **深浅主题**：首页右上与工作台左栏底部可切换；选择写入 `localStorage`，刷新保持；默认深色，游戏画面固定深色，不随应用主题反色。
- **可拖拽分栏**：游戏与对话之间有一条横向拖条，拖动可让对话变大且输入框仍可见；尺寸刷新保持，双击拖条复位。左工程栏与证据栏也可拖动，并在最小/最大宽度内 clamp。
- 目标布局在 1280×800 下游戏与对话同屏且无横向滚动；≤1100px 时左右栏变抽屉，拖条隐藏。

> 三栏、主题与可拖拽分栏只是降低学习成本、适应阅读习惯，不是差异化。差异化仍是任务编译卡、结构化配方 diff、用户确认的创作底线，以及同一 Issue 的回归证据；如果这些没进入主路径，界面像谁都不重要。

## 证据链：四件事都必须出现在界面上

| 问题 | 用户看到什么 | 机器留下什么 |
|---|---|---|
| **AI 要做什么** | 任务编译卡：理解为 / 目标 / 基于哪个版本和证据 / 不会修改什么 / 完成标准 | `task-brief.json`（含 `compilerVersion`）；服务端重新计算基础版本、契约、允许操作，前端只能改目标、限制与选中对象 |
| **实际改了什么** | 每个工具步骤对应的真实配方 diff；当前版本与 AI 候选分开 | 只有类型化 PatchOp；前后 recipe；候选 `buildId`；不执行模型提交的任意代码 |
| **机器如何判定** | “机器检查”与“AI 自述”分栏；失败项带检查 ID 与证据 | Schema、创作底线、内核 BFS、固定种子重放、真实浏览器回放；只有同一 `buildId` 的检查全部通过才进入人工审核 |
| **出问题如何回归** | 问题条：`让 AI 修复` / `查看为什么` / `回到最近可玩版本` | Issue 串起复现证据、repair brief、候选版本与回归结果；回退不删除失败候选与证据 |

三条硬规则：

1. AI 的补丁不能修改创作底线；违反会被 `CONTRACT_VIOLATION` 拦截，并进入 concern。
2. 自动可判定的问题，必须**同一检查由失败变通过**才算修好；体验类问题只能到“待你试玩确认”。
3. 用户口述的问题无法复现时只能是 `cannot_reproduce` / `awaiting_review`，不能自动标成已解决。

## 自动体检与三档审查

右侧“证据与设置 → 验证”顶部有两种能力：

1. **自动体检（本地规则，0 次模型调用）**：共 29 条规则，覆盖网格、知识、卡牌、对话、素材；打开版本或保存改动后自动运行。常见问题包括钥匙被锁在门后、门要的钥匙数量不够、物体在墙里/叠格、规则引用不存在的对象、机关门永远打不开、答案不在选项里、单选题多个答案、卡牌费用超过每回合能量、牌组引用不存在的卡、对话跳到不存在的节点。
2. **三档审查方式**（点“运行验证”时按所选方式执行）：
   - **本地规则**：只跑 29 条规则，不调用模型。
   - **云端 AI 审查**：1 次模型调用，审查配方逻辑；结论只是建议，不能直接改配方。
   - **本地 + 云端**：本地结论与云端结论分开标注，仍然只做建议。

每条问题有两个动作：

- **一键修复**：6 条规则支持，全程不调用模型；修复结果存为新草稿，照常经过创作底线检查并自动重新验证，原问题提示随后消失。
- **让 AI 修**：把问题描述填进对话框，你确认后再发给 AI；AI 仍需走受约束补丁与同一检查回归。

云端审查的边界：

- 需要先在设置里连接模型；未连接时云端选项不可选，只跑本地规则。
- 发送给模型的是当前配方、本地体检结论与已确认底线；不发送 API Key、本机路径或无关文件。
- 模型返回的 quickFix / ops / 补丁字段一律丢弃；AI 审查不能直接修改配方。
- 云端失败或跳过时，界面如实显示失败原因，并回退展示本地体检结论；不会把失败说成通过。
- 每次云端审查最多产生 1 次模型调用；状态里显示模型名、调用次数与 token。

> 本地体检与云端审查是“先便宜地查、再决定是否花钱让模型看”的分层；不是用 AI 替代规则内核，也不是让 AI 直接改代码。

## P17 素材、对话与画面

- **素材**：右侧「证据与设置 → 素材」上传图片/音频；图片可“设为背景”，音频可“设为音乐”，保存新版本后生效。背景、BGM、卡面插画在工作台/播放页渲染；音频支持 MP3/OGG/WAV（≤12 MiB）。
- **对话**：旁白在画面左下角逐字出现（约 24ms/字）；点击补全整句，再点进入下一句；有选项时在正中半透明遮罩上选择；右上角可开系统朗读、关 BGM。
- **画面**：默认自动等比缩放；工具栏可关闭自动适应，用 − / ＋ / 1:1 手动缩放（50%–200%），选择刷新后保持。
- **新建**：新游戏是空白骨架，不再带“末班车”等样例剧情/示例题。
- **导出**：点导出可选“网页版（不含 Node）”或“便携版（含 Node，约 +80MB）”，完成后自动触发浏览器下载。
- **卡牌**：HTML 卡面、扇形手牌/桌面平铺切换、对手意图卡与行动日志。


## P18 导出素材、配对与横板舞台

- **导出素材**：图片/音频会写入导出包的 `game/assets/` 和 `assets.json`，导出的独立游戏也能显示背景、播放 BGM。
- **节点级对话**：每个对话节点可单独选背景、音乐、语音素材；语音留空时用系统朗读。编辑器在对话表格里选，运行时优先节点设置。
- **单词配对**：新增 `matching` 题型；运行时左右两栏点击配对，内核按一对一判定，verifier/playtest/编辑器都支持；单词远征现为 33 题（含 3 道配对）。
- **组件积木**：编辑器顶部“组件积木”把钥匙/门/守卫、单选/配对题、攻击牌/敌人、旁白/结局**拖到地图格子或列表**即落位（P22 起支持拖拽吸附，点击仍可用）；卡牌“扇形/平铺”在“外观与声音”里。
- **自定义类型**：首页类型可选“我自己定义”，按描述映射到最接近的支持模式包，并明确提示不能凭空生成新内核。
- **外观/音频编辑器**：背景/地板/墙/强调/文字色、格子大小、声音、背景图、BGM、卡牌布局；卡牌描述与插画素材可改。
- **横板舞台**：所有游戏统一 16:9；工作台和播放页都是横板，对话不再竖版重叠。
- **提示样式**：撤回 P17 的 toast 重设计，恢复原边框/阴影/关闭按钮，仅把原底纹按主题加深。

边界：积木支持拖拽吸附与点击两种落位方式，但只是结构化编辑配方，不是通用可视化编程；自定义类型只映射到 5 个受支持模式；卡牌演出为伤害/格挡飘字与受击抖动，不是逐帧动画；导出素材已内嵌并加载，但导出包内的音视频播放尚未逐项自动化。

## 入口速查：背景/音乐怎么插、积木在哪

- **插入背景 / 音乐**：工作台顶部点 **外观素材**（或游戏画面左上角 **＋ 插入背景 / 音乐**）→ 右侧“素材”页签 → **＋ 上传图片或音频**（也可拖文件进去）→ 点素材上的 **设为背景 / 设为音乐** → 回工具栏 **保存为新版本**。
  面板顶部会显示“当前背景 / 当前音乐”，可一键取消。挂载写在 `presentation.assets` 的槽位（background / music / dialogue-bg），导出时素材一起打包。
- **积木在哪**：工具栏中间的 **积木搭建** 就是编辑模式（原“编辑”改名，避免误解），游戏画面左上角 **拼积木改规则** 直达。进去有两层：上面是**组件积木**（钥匙/门/守卫、单选/配对题、攻击牌/敌人、旁白/结局，可拖拽吸附），下面是**规则积木**（“当·如果·那么”三段）。
- 详细图文步骤见 [docs/how-to-assets-and-blocks.md](docs/how-to-assets-and-blocks.md)。

## P19 规则积木与加长样例

- **规则积木**：解谜/潜行编辑器的“当 · 如果 · 那么”三段积木，直接拼出 Schema 允许的 GridRule（事件 × 条件 × 效果），可增删改；all/any/not 等嵌套条件仍在下方结构化数据里编辑。
- **组件积木**：按模式包提供的点击拼接（道具/门/守卫、单选/配对题、攻击牌/敌人、旁白节点/结局）。
- **加长样例**：首页模板新增 06 深库三进（19×9、两把钥匙、机关门）、07 熔炉连战（5 场战斗、12 种卡牌）、08 长夜渡轮（16 节点、4 个可达结局）；单词远征加到 33 题含 3 道配对。三个新样例全部由生产 verifier 判定 passed。
- **卡牌演出**：出牌/受击飘字（伤害红、格挡蓝）与受击抖动；对手“最近行动”卡片化显示。
- 生成器与反馈记录见 [docs/competition/evidence/long-samples-2026-11-14/README.md](docs/competition/evidence/long-samples-2026-11-14/README.md)。

## 诚实边界

- `world`（轻开放世界）模式包未实现，不新增；正式支持仍是五个包。
- 外部工程导入只支持 Tiled 正交 JSON 地图（≤20×20，映射到解谜/潜行包）；不支持 Unity/Godot 工程、等距/六边形地图、无限地图和压缩图层，图块贴图不会转成素材。
- 自动验证不证明题目事实正确、卡牌平衡或游戏好玩；它只覆盖声明的结构与规则范围。
- 干净 Windows 机器、启动器双击、中文/空格路径、断网、只读安装目录：未验证。
- 新手可用性测试：未执行；不伪造成功率或用户反馈。
- 真实模型 Key 只在后端会话内存；不写入项目、日志、证据或导出包。
- 云端 AI 审查需要有效模型，真实成功样本只有 1 次（单模型）；云端审查永远只是建议，不能替代机器检查或直接改配方。
- 浏览器真实试玩需要本机 Chrome/Edge；没有浏览器时规则检查仍可做，但不能声称“真实通关”。
- P13 界面截图由真实浏览器 e2e 生成（[creation-flow-2026-11-13](docs/competition/evidence/creation-flow-2026-11-13/)）；其中 `initial-generation.png` 是 demo 工作台截图，真实模型证据另见 [p13-real-model-2026-11-13](docs/competition/evidence/p13-real-model-2026-11-13/)。新手可用性测试仍未执行。

## 能力边界

- 只支持五个模式包；不做开放世界引擎、实时动作、多人联机、云端协作。对话包是配方驱动的确定性状态机，不支持运行时实时生成对话。
- 浏览器真实输入试玩需要本机 Chrome/Edge（或设置 `ZAOWAN_CDP_URL`）；发行包内只有 Node 运行时，不含 Chromium。
- 不执行用户或模型提交的代码；知识题不支持代码沙箱，编程题只做“读代码选输出”。
- 不做语义判分、模糊匹配或模型判分。
- 导出包不需要模型，也不含创作后台；源码重新构建需要联网安装依赖。
