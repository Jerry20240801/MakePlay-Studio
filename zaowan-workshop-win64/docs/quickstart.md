# 快速上手：5 分钟走完主流程

> 适用：P16 创作工作台（含自动体检、一键修复与三档审查；3 分钟演示与新手测试仍待补，见 [implementation-status.md](implementation-status.md)）。

这条路径只做六件事：**选模板玩到 → 让 AI 改 → 制造/触发问题 → 让 AI 修 → 回退 → 导出**。模型响应慢时实际耗时会超过 5 分钟；不要为了赶时间跳过验证。

## 0:00–0:30 启动，先看 AI 状态

```bash
pnpm install
pnpm build
pnpm start
```

打开终端里打印的 `http://127.0.0.1:端口/`。

**预期界面**

- 左侧是工程栏：已有工程列表 + 顶部“新建游戏”；右侧是大标题、一句话输入、主按钮“开始创作”和八个模板卡。
- 右上角只有一个 AI 状态入口：“AI 已连接 · 模型名”或“AI 未连接 · 设置”。
- 页面提供深/浅主题切换（首页右上、工作台左栏底部）；**默认浅色**，点一下可切到深色，选择刷新后保持。
- 首页不出现 CDP、Recipe、ContractSet、buildId。
- 想在空白工程里自己改：点左栏“新建游戏”，会直接进入名为“未命名游戏”的工作台。

**失败时怎么办**

- 页面提示“尚未构建”：先跑 `pnpm build`，再 `pnpm start`。
- 打不开或端口被占用：以启动日志里实际打印的地址为准；也可设置 `ZAOWAN_PORT`。
- AI 未连接：模板路径不受影响，继续第 1 步；想法路径不会生成，只能建骨架或手动编辑。需要真实生成时去“AI 设置”填 Base URL、模型 ID、Key，并点“测试连接”。
- 不想配模型也能走完第 1、3、5、6 步；第 2、4 步的“AI 修改/修复”会明确不可用，这是诚实降级，不是故障。

## 0:30–1:30 选一个模板，先玩到

点“使用模板”中的任意一张卡（解谜“钥匙与出口”最适合后面制造问题）。

**预期界面**

- 直接进入工作台，中央是真实游戏预览，不是配置表单。
- 左栏是工程列表；当前工程下展开“会话”，顶部按钮是“新建会话”。
- 游戏与对话之间有一条横向拖条：向下拖让游戏变大，向上拖让对话变大；对话变大时输入框仍可见。双击拖条恢复默认。
- 右栏默认折叠。
- 游戏下方有三个动作：“试玩一下”“让 AI 改一个地方”“导出游戏”。

**操作**

- 网格类：方向键/WASD 移动，`E` 开门，`Space` 等待，`R` 重开。
- 知识类：鼠标选项或数字键；卡牌类：点牌/结束回合；对话类：`Enter` 继续、数字键选择。

**失败时怎么办**

- 游戏区空白：先点一下游戏画布再按方向键（聊天框聚焦时按键不会驱动游戏）；仍空白就看浏览器控制台和终端错误。
- 按键不生效：确认焦点在画布，不是对话输入框；对话包用 `Enter` 与数字键。
- 看不到左栏或三栏：窗口太窄时左右栏会变抽屉；如果仍看到旧的单列平铺界面，说明前端资源未更新，重新 `pnpm build` 后再试。

## 1:30–2:30 让 AI 改一个地方

点“让 AI 改一个地方”，输入一句具体、可检查的要求，例如：

> 把钥匙移到出生点右边一格，不要动门和胜利条件。

发送前先看任务编译卡。

**预期界面（任务编译卡）**

```text
理解为：修改当前版本
目标：把钥匙移到出生点右边一格
基于：v2 · 2 项检查 · 最近操作 3 步
不会修改：门 door-1、胜利条件（已确认底线）
完成标准：非空配方 diff + 同一检查通过 + 真实浏览器试玩
[修改目标与限制] [开始修改]
```

点“开始修改”后：

- 下方时间线逐步出现“AI 说 / 工具调用 / 机器结果”，每个改配方的步骤都能点开看 diff。
- 结束后出现“AI 候选”，中央可切换“当前版本 / AI 候选”。
- 右栏“改动”显示前后配方差异；“验证”显示机器检查与 AI 自述分开的结果。

**失败时怎么办**

- 按钮不可用/提示未连接：去“AI 设置”；401/403 是 Key 或端点问题。
- `MODEL_PROTOCOL_UNSUPPORTED`：端点不支持工具调用，换一个兼容 Chat Completions 工具调用的模型。
- `BUDGET_EXCEEDED`：这次没有收敛，不算完成；把要求拆小后重试。
- `CONTRACT_VIOLATION`：AI 的改法碰到你确认的底线，已被后端拦截；看冲突项，改要求，不要删底线来“绕过”。
- `BROWSER_UNAVAILABLE`：本机没有 Chrome/Edge，或无法启动；装浏览器或用 `ZAOWAN_CDP_URL` 连接外部浏览器。此时只能看规则检查，不能声称真实通关。
- 只有解释、没有非空 diff：不算生成/修改成功；把要求写得更具体后重试。
- 验证是 `partial`：规则过了但缺真实浏览器证据；运行真实试玩补齐，不要当通过。

## 2:30–3:15 制造或触发一个问题

有两条路。想做“同一检查由失败变通过”的完整回归，用 A；只验证“用户口述问题”的诚实状态，用 B。

### A. 制造一个机器能复现的问题（推荐用于演示）

1. 切到“编辑”，把钥匙 `key-1` 移到门后的房间（或把门改成需要钥匙、但钥匙在门后）。
2. 保存为新版本。
3. 点“运行验证”。

**预期界面**

- 游戏上方出现问题条：“发现 1 个可复现的问题：钥匙拿不到，当前版本无法通关。”
- 问题条只有三个按钮：`让 AI 修复`、`查看为什么`、`回到最近可玩版本`。
- 右栏“验证”自动打开，失败检查带 ID（例如 `reachable_goal`）和证据；原始 JSON 折叠在技术细节里。

### B. 口述一个试玩中发现的问题

点“报告问题”，写清楚“我做了什么、期望什么、实际什么”。如果有最近操作记录，会附上最近 50 步；没有就手填步骤。

**预期界面**

- 问题进入“待补充/无法复现”或“待你试玩确认”，不会自动变成“已解决”。
- AI 必须先问操作步骤，不能直接说“已修好”。

### 选择审查方式（本地 / 云端 / 两者）

验证页签顶部有审查方式选择：

- **本地规则**：默认，0 次模型调用；29 条规则会随版本打开/保存自动跑。
- **云端 AI 审查**：需要先在设置里连接 AI；1 次模型调用，结果只是建议，不能直接改配方。
- **本地 + 云端**：先跑本地，再把配方、本地结论与已确认底线发给云端；两类结论分别标注。

点“运行验证”会按当前方式执行：本地模式只跑机器检查；云端/两者会在机器检查后追加一次审查。也可以点“只重新审查（不跑机器检查）”。

**一键修复 / 让 AI 修**

- 6 条本地规则带“一键修复”：不调用模型，生成新草稿并自动重新验证；原问题提示会消失。确认候选后可采纳。
- 其他问题点“让 AI 修”：会把问题描述填进对话框，你确认后再发送；不要让 AI 直接改，仍然走任务卡与回归检查。
- 云端审查失败时，列表会回退显示本地结论，并显示失败原因；不要把它当成“没有问题”。

**失败时怎么办**

- 云端选项灰色：先在“AI 设置”连接模型；未连接时只用本地规则。
- 云端显示“认证失败/超时”：检查 Base URL、模型 ID、Key 和网络；本地规则仍然有效。
- 一键修复后仍是失败：看修复后的候选版本与检查；问题没消失就退回或让 AI 修，不要直接采纳。
- 审查结论说“没问题”但机器检查失败：以机器检查为准；AI 审查不是通过凭证。

**失败时怎么办**

- 验证失败但没有问题条：手动打开右栏“验证”确认失败项；确认你验证的是刚保存的版本（看 buildId/版本号），刷新后仍未出现就记录为缺陷。
- 问题条文案是技术错误：展开“查看为什么”应有人话原因；只有 raw error 说明前端映射未完成。
- 口述问题被直接标成已解决：这是错误，不能接受；应回到 `awaiting_review` 或 `cannot_reproduce`。

## 3:15–4:15 让 AI 修，并看同一检查回归

点问题条上的“让 AI 修复”。

**预期界面（修复任务编译卡）**

```text
理解为：修复当前版本的问题
目标：钥匙拿不到，把钥匙移到可达位置
基于：v3 · 失败检查 reachable_goal · 浏览器操作轨迹
不会修改：门 door-1、胜利条件（已确认底线）
完成标准：同一检查通过 + 新候选真实浏览器通关
[修改目标与限制] [开始修复]
```

修复结束后：

- 同一个失败检查由 `failed` 变为 `passed`；报告绑定新候选的 `buildId`。
- 有浏览器回放证据（输入轨迹、截图、控制台无错误）。
- 右栏能对比修复前后配方；失败候选与旧证据仍然保留。
- 机器可判定的问题自动 `resolved`；体验类问题只到“待你试玩确认”。

**失败时怎么办**

- 同一检查仍失败：Issue 回到 `open`，不会谎称修好；把范围缩小或补充约束后重试。
- 只有规则通过、没有浏览器证据：状态应为 `partial`/待补，不能算修复完成；运行真实试玩。
- `CONTRACT_VIOLATION`：AI 想改底线，已拦截；看冲突项并改要求。
- `cannot_reproduce`：先补操作步骤或最近操作记录，再谈修复。
- 修复后直接显示“已解决”但你没试玩过：如果这是体验类问题，属于错误；应显示“待你试玩确认”。

## 4:15–4:40 回退到最近可玩版本

点问题条或版本区的“回到最近可玩版本”。

**预期界面**

- 当前版本切回最近通过验证的可玩版本；游戏可立即试玩。
- 失败候选、验证报告、截图与输入轨迹**不被删除**；版本列表仍能看到它。

**失败时怎么办**

- 找不到回退按钮：在右栏“版本”里手动选最近一个已验证版本；如果版本列表也没有，记录为缺陷。
- 回退后游戏仍不可玩：重新运行验证；确认选中的是已验证版本，而不是失败候选。

## 4:40–5:00 导出，并在工作台外运行

点“导出游戏”。

**预期界面**

- 生成独立 ZIP：`game/`、`recipe.json`、`contracts.json`、`manifest.json`、`source/`、`runtime/node.exe`、`Start-Game.cmd`。
- 导出包不需要模型，也不含创作后台。

**操作**

1. 把 ZIP 解压到仓库外的目录（路径可含中文与空格）。
2. 双击 `Start-Game.cmd`，确认游戏能玩、没有模型请求。

**失败时怎么办**

- 提示缺少 `runtime/node.exe`：换完整发行包，或本机安装 Node 20+。
- 双击无反应/被杀软拦截：看命令行窗口错误；把目录加入信任后再试。
- 源码重建失败：重建需要联网安装依赖；离线可运行不等于离线可重建。

## 可选：继续这个话题，以及重启后的恢复

- 任务结束后输入框变为“继续这个话题”；发送后创建同 `threadId` 的新运行，`parentRunId` 指向上一次，基础版本取你当前选中的版本。
- 主题与分栏尺寸都会写入本地存储；刷新后主题、游戏/对话比例、左右栏宽度保持。
- 想换一个话题：点左栏“新建会话”，当前会话视图清空、输入框聚焦；发送第一条要求后才创建新线程，旧会话仍保留在工程下。
- 左栏“会话”按最近活动排序；点会话能看各次运行、候选与最终结论。
- 重启服务后：线程与历史摘要应恢复；重启前未结束的运行标为 `cancelled` + `interrupted`，提示“服务重启，未继续执行”，不会自动重放工具或模型请求。

**失败时怎么办**

- 线程列表为空但磁盘有证据：看 `projects/<project-id>/runs/*/run.json` 是否存在；缺 `run.json` 就是恢复索引缺口。
- 重启后旧任务自动继续跑：不可接受；应只标记中断，不自动重放。

## 5 分钟后自检

- [ ] 首页左栏能看到工程；点“新建游戏”能进入空白工程。
- [ ] 深浅主题切换后刷新仍是同一主题；两种主题都没有横向滚动。
- [ ] 拖动游戏/对话分栏后对话变大、输入框仍可见；刷新保持，双击复位。
- [ ] 两次点击内进入一个真正能玩的游戏。
- [ ] 工作台“新建会话”清空当前会话，旧会话仍保留。
- [ ] 发送前看见了任务编译卡（目标/基于/不会修改/完成标准）。
- [ ] AI 的修改有非空配方 diff，而不是只有聊天。
- [ ] 机器检查与 AI 自述分开显示。
- [ ] 问题条能一键修复，并看到同一检查由失败变通过。
- [ ] 回退后失败候选与证据仍在。
- [ ] 导出包在仓库外能独立运行。

## 可选：给自己的游戏换背景、加音乐、拼积木

三步就能换掉舞台背景，详细图文见 [how-to-assets-and-blocks.md](how-to-assets-and-blocks.md)：

1. 工作台顶部点 **外观素材**（游戏画面左上角也有 **＋ 插入背景 / 音乐**）。
2. 在“素材”页签的虚线框里点选或拖入文件 → 点 **设为背景** / **设为音乐**。
3. 回工具栏点 **保存为新版本**，画面立刻换背景；导出时素材一起打包。

想改玩法规则就点工具栏的 **积木搭建**（画面左上角 **拼积木改规则**）：组件积木从调色板**拖到地图格子**落位（点击添加也保留）；规则积木把帽子/条件/动作积木**拖进当·如果·那么吸附区**，拖回工具箱即拆下，点“放入配方”提交。

- 运行证据：`runs/<run-id>/`（`run.json`、`task-brief.json`、`events.jsonl`、`checks.json`、`report.json`、`playtest.json`、`inputs.jsonl`、`screenshots/`）。

pnpm typecheck
