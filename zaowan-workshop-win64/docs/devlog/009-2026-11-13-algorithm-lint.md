# 009 · 2026-11-13：算法体检与一键修复

## 为什么
用户要求“能算法干的活就交给算法，尽量减少调用次数”。实测“钥匙在门后”这一类缺陷完全可以由规则确定解法，不需要模型。

## 做了什么
- `packages/verifier/src/lint.ts`：29 条纯函数规则，输出 `{ruleId, severity, message, targets, quickFix?}`；quickFix 是普通 PatchOp 列表。
- 关键规则“钥匙在门后”：把门和机关门当墙做洪水填充，求出不经过任何门可达的区域；所需道具不在区域内时，在区域里选离原位置最近的空地作为移动目标。只在单门、无机关门时下结论（多门链需要状态搜索，避免误报）。
- 一键修复走 `apply_recipe_patch` 同一通道：zod 校验、配方校验、契约拦截、diff 都复用；版本来源 `algorithm`，备注“算法修复（未调用 AI）”；修复后自动验证并对同一版本的问题单做回归结案。
- Agent 首条消息附带体检结果（info 级除外，最多 8 条）。
- 顺带修了右侧证据面板内容被挤出可视区的布局 bug。

## 踩坑
- 熔炉决斗样例含加能量的牌，所以“费用超能量”规则正确地不报；测试里先去掉加能量效果。
- 搜索失败状态名是 `exhausted`，不是 `not_found`。
- 体检通过不代表游戏没问题：UI 写“没有发现常见问题”，不写“没有 bug”。
