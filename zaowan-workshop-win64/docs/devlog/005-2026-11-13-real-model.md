失败的那 8 次不是模型能力问题，而是产品侧三个缺陷暴露：

1. run_rule_checks 在 partial 时被当成失败返回，模型以为补丁没生效，反复重跑检查。
2. 工具描述没有列出补丁 op 与字段，模型倾向先 read_evidence / compare_versions 探索，而 read_evidence 读不到验证报告（证据写到了另一个运行目录）。
3. Agent 成功后没有停止循环，prepare_review 之后还会再请求一次模型；测试关闭服务时运行清单（events/model-usage/plan-summary）没写完。

## 修复

- run_rule_checks 接受 partial（ok=true，并在描述与系统提示里说明 partial 是正常状态，下一步是浏览器重放）。
- apply_recipe_patch 的工具描述列出全部 op 与字段，并给出 move_entity 示例；系统提示固定六步流程，禁止 create_candidate / read_evidence / compare_versions 探索。
- run_rule_checks 把 checks.json / report.json 同步写入 Agent 运行目录，read_evidence 可读。
- prepare_review 成功后立即停止循环，保证运行清单落盘。
- 浏览器重放成功并绑定证据后，把重新验证的 report/checks/manifest 写回运行目录（之前只存在内存里）。
