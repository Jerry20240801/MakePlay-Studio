# 3 分钟演示 Runbook（P13 主线）

> 只演主线：模板 → 想法生成 → 出问题 → 修复/回退 → 导出。不要展示内部术语或无关证据。
> 本文件是演示脚本，不是录制视频；录屏与新手测试仍未执行。

## 演示前

- 本机 Edge/Chrome 可用；node scripts/build.mjs 已执行；node scripts/start.mjs 已启动。
- 模型已连接到可用的 OpenAI 兼容端点（演示真实生成时）。如果现场不能连模型，明确说“这段是示例回放”，不要冒充真实模型。
- 准备两个项目：
  1. 一个空工作台 / 首页（用于模板与想法入口）。
  2. 一个已复现问题的项目：用 tests/fixtures/key-behind-door.json 作为候选版本并验证失败，使问题条出现（可提前用 API/测试脚本准备，不在现场写代码）。

## 0:00–0:20 模板：两次点击玩到

1. 首页只指三处：一句话输入、5 个模板、AI 状态。
2. 点“使用模板”（钥匙与出口）→ 工作台。
3. 中央游戏直接可玩；按方向键走两步，说明“真实内核，不是截图”。

## 0:20–1:20 想法：真实生成第一版

1. 回首页，输入：“做一个钥匙门解谜小游戏：玩家从左上角出发，找到钥匙打开门，走到出口；不要做第二关。”
2. 点“开始创作” → 工作台自动出现任务卡与运行。
3. 指任务卡：理解为 / 目标 / 基于哪个版本 / 不会修改什么 / 完成标准。
4. 指步骤卡：AI 说 → 工具调用 → 机器检查 → 浏览器试玩；强调“AI 自述与机器证据分栏”。
5. 指候选切换：当前版本 / AI 候选；候选不会自动覆盖。

## 1:20–2:30 出问题 → 让 AI 修 → 同一检查回归

1. 打开准备好的问题项目；问题条显示“已复现 + 检查 ID”。
2. 点“查看为什么”：先人话原因，技术细节折叠。
3. 点“让 AI 修复”：任务卡自动带同一失败检查、版本与操作轨迹。
4. 运行结束后：指“同一检查由 failed 变 passed”和浏览器回放，不指模型自述。
5. 点“回到最近可玩版本”：说明失败候选与证据仍保留，不删除历史。

## 2:30–3:00 导出

1. 点“导出游戏”，展示 ZIP 与 Start-Game.cmd。
2. 一句话收尾：AI 在受约束配方上改，用户确认底线，机器与真实浏览器给证据，出问题用同一检查回归。
